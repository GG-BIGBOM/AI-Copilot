## A · AI Agent 开发版

**架构与编排打头。**

### AI Copilot —— 旺店通旗舰版 ERP 的知识库 Agent

一个带引用的 ERP 问答 Agent。已上线：<https://liushun666.cn/>
Python / FastAPI / Pydantic AI / PostgreSQL + pgvector / Next.js 15。

**最值得说的一个架构决定：把答案生成收进"终结工具"。**

M7 改成 Agent 之后，41 题上准确率 87.8%、幻觉率 12.5%。翻失败样本，
成因收敛成四条（检索词漂移、材料串味、拒答闸门变软、换了 prompt），
而四条的公因子只有一个：**Agent 被允许拿原始材料自己写答案**。

所以不修那四条，改结构：把工具分成"普通工具"和"终结工具"，
`answer_kb` 的返回值**就是**给用户的最终答案，Agent 不许改写、也拿不到材料。
它内部跑的是那条被量到 100% 的直路，一个字没改。

| | M7 | M10 |
|---|---|---|
| 准确率 | 87.8% | **100%** |
| 幻觉率 | 12.5% | **0%** |

⭐ **模型只能决定"要不要查"，不能决定"答什么"。**
代价也写了：模型看不到答案，调试变难——这是后来做 OpenTelemetry span 树的动因。

**第二个 Agent：加了，量了，默认关着。**
高风险答案出稿后过一个 verifier。56 题只差一个开关，
四条硬指标 0.0% → 0.0%，**一个点没动**——因为幻觉率本来就已经在地板上。
22/56 的答案花了一次校验调用，2 条被标注、0 条误报。
ADR 里写清了什么条件下我会打开它。
⭐ 不为多而多：多 Agent 编排一问"它让哪个指标动了几个点"就穿帮。

**上下文工程**：固定 6 条窗口 → 按字符预算装配 + 滚动摘要。
长会话跨窗口解析 54.5% → **90.9%**，而**对照组一分没掉**。
⭐ 摘要**不调模型**——跨窗口那几道题的答案全是用户自己打过的原字，
让模型重写一遍换不来更准，换来一次调用、一份延迟和一条会写错的路。

**其他**：MCP server（Claude Desktop 直连知识库，`user_id` 不是工具入参）、
提示注入三层防线（注入成功率 44.4% → **0.0%**）、
Postgres `FOR UPDATE SKIP LOCKED` 做任务队列（不引入 Redis / Celery）。

## B · AI FDE / 交付工程师版

**交付与运维打头。**

### AI Copilot —— 从零到公网上线，一个人交付的 ERP 知识库 Agent

已上线：<https://liushun666.cn/>。语料 746 篇 / 4568 块，
**一台 2 核 1.6GB 内存的 ECS**，没有 Docker、没有 Redis、没有独立向量库。

**这个项目真正在解决的问题**：一个 ERP 实施顾问每天要回答几十遍同样的问题。
答错的代价不是"不好用"——**一个编出来的配置步骤，能让客户第二天的订单卡在仓库里**。
所以核心不是"能不能答"，是**"敢不敢让它答"**。

**1.6GB 内存下的三条硬约束**（每一条都是交付时算出来的，不是估的）：
前端静态导出且必须本机构建（`next build` 峰值 1GB+，服务器上必 OOM）、
加 2GB swap、服务器端不跑 PDF 的 ML 管线。
上线前实测回收了 264MB 常驻内存（列了每个进程的去留和理由）。

**部署是一条命令七步**：本机自检 → 本机构建前端 → 推后端 → 推勘误层 →
同步 systemd 单元 → 推前端产物 → 迁移重启。
⚠️ 里面有一条不是洁癖的检查：**CRLF 闸门**。一个 Windows 上的补丁脚本
用 `Path.write_text` 改了一行 `deploy/backup.sh`，Linux 上 bash 读到
`pipefail\r`，**备份从此每天照常"跑完"、每天什么都没备份**。
⭐ 备份坏掉是所有失败模式里最坏的一种：发现它的那一刻，往往正是你需要它的那一刻。

**客户已经在用的 AI 工具能直接接进来**：`copilot mcp` 起一个 MCP server，
Claude Desktop / Cursor 不用改造就能问知识库、拿到带引用的答案。
⚠️ 做它时第一件事是想清楚 `user_id` 从哪来——它**不是工具入参**，
凡是能出现在工具签名里的东西，一句 prompt injection 就能让模型去填。

**交付质量是量出来的，不是声称的**：七条硬指标写进一份契约文件，
`eval/gate.py` 读证据逐条对照，退出码 0 / 1。三种结局分得开，
第三种叫 **UNRELIABLE**——判分器那天自己失效了，那一轮的数字什么都不能算。

**安全基线**：关 SSH 密码登录 + fail2ban，**在放数据之前做**（实测到的爆破量在文档里）；
邀请码制注册；上传走 zip 炸弹防护；私有图片走鉴权路由而不是公开 URL。

**还没做完的我也写下来了**：一份 `ISSUES.md` 专门记「知道了但这一轮没修」，
每条都写**什么条件下必须修**——没有触发条件的台账等于许愿池。

## C · AI 产品经理版

**指标与取舍打头。**

### AI Copilot —— 一个把"敢不敢让它答"当成核心指标的 ERP 助手

已上线：<https://liushun666.cn/>

**问题定义**：ERP 实施顾问的重复问答。⚠️ 这个场景里，
**答错比答不出贵得多**——用户照着一条编出来的路径去点，
点不到会先怀疑自己、再怀疑版本，最后打电话给顾问。所以第一个指标不是准确率，
是**幻觉率，红线 = 0**。

**四条红线指标，一条都不许非 0**：
高风险幻觉率、假引用率、跨 ERP 版本串台率、提示注入照做率。
它们的共同点是"错了会伤到人"。另有三条质量线（准确率、拒答正确率、常识回答成功率）
定在"比最近一次实测低几个点"——⭐ 卡在实测值上会让门禁天天为噪声变红，
**而变红多了就没人看了**。

**几个真实的产品取舍：**

| 取舍 | 决定 | 依据 |
|---|---|---|
| 常识兜底 | 开一半：概念可以讲，界面路径/参数值绝不凭记忆编 | 一个连「品牌方是什么」都拒答的助手，用起来像坏的 |
| 混合检索 | **一度默认开，后来关回去了** | 它把裸粘贴编码的召回从 6/15 救到 15/15，同时把幻觉率从 0% 顶到 10% |
| 第二个 Agent | 做了，**指标没动，默认关着** | 幻觉率已经是 0，它只可能把对的答案降级成拒答 |
| 滚动摘要 | 不调模型 | 那三个"用哪个模型/存哪/阈值多少"的问题，只在"必须用模型"的前提下才存在 |

⭐ 混合检索那一条最值得讲：**当初定"默认开"靠的是一个免费指标，
而那个指标对「该拒答的题被劝答了」结构性失明**——no_answer 类的题没有
期望来源，按定义就不进那个分母。推翻记录补在**同一条 ADR 下面**，
没有另起一份。

**改前必须先量**：每一个会改变答案的开关都先做成开关、默认关，
拿同一份题集跑 A/B，两臂只差那一个变量。
⭐ 而这条规矩能落地，靠的是**把量的成本降到零**：
长会话那套题有一档免费的「信息在不在上下文里」，零成本、确定性判定。
**一条要花钱才能遵守的规矩，迟早会变成一条没人遵守的规矩。**

**产品还缺什么，我也知道**：线上追踪默认关着，所以"线上这一轮 9 秒花在哪"
目前说不出来；真实用户只有 1 个（就是我自己），所以旧路由还不能删——
**灰度到 3 个注册账号谈百分比，等于观察零样本**。
