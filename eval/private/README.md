# 私有库评测

**为什么单独有这一组。** M8 的 41 题全打公共库（`user_id=None`），
私有库的检索质量从来没被度量过——而私有库和公共库有两个实打实的区别：

1. **可见范围是 `公共库 ∪ 我的文档`**，检索要在两个来源里竞争。
   一个只在公共库上验过的重排配置，未必能让私有文档在混合池里冒头。
2. **私有文档没有语雀那样的章节结构**（用户传的是 docx、截图、扫描件），
   切出来的块形状不一样。

## 怎么跑

```bash
cd backend

# 1. 把夹具文档灌进某个用户的私有库（只需一次；改了夹具要重灌）
uv run copilot ingest ../eval/private --owner you@example.com

# 2. 跑私有库那组题
uv run python ../eval/run.py --as-user you@example.com --tag private-1

# 只验检索、不花钱
uv run python ../eval/run.py --as-user you@example.com --check
```

不带 `--as-user` 时跑的仍然是公共库那 55 题，行为和以前完全一样——
两组题**不混跑**，混跑等于把两个不同的题集算进同一个准确率，
而报告上看不出来。

## 夹具文档的写法

`客户A-实施配置约定.md` 里的每个数字都是**特意编的**，且刻意和语雀语料
不重合（比如"中通日单量上限 800 单"——公共库里没有任何一篇提到星辰电商）。

这是这组题唯一的判据来源：如果模型答出了 800，那它一定读到了私有文档；
如果它答的是公共库里某个相近的数字，就说明私有文档在混合检索池里被挤掉了。

**所以夹具的事实一旦和公共库撞车，这组题就失去意义。** 加新事实前先
`grep` 一下语料。

### 两份夹具，不是一份（M11 P3，2026-08-20）

`客户B-实施配置约定.md`（远岸家居）在**和客户A完全相同的字段**上给了
不同的值：中通 1500 单 / 安全库存 50 件 / 盘点 25 号 / 对账以 ERP 发货单为准。

为什么必须有第二份：只有一份夹具时，「答对」有一条很便宜的作弊路径——
把那份文档整个背下来就行，**根本不用分辨问的是谁**。两份一撞，
「星辰的中通上限」和「远岸的中通上限」就成了两个必须分开的答案。
这也是真实场景：一个实施顾问手上同时有好几家客户的配置约定。

> ⚠️ 上面那条「夹具事实不许和公共库撞车」有一类**故意的例外**：
> `priv-conflict-*` 那几题就是要撞。它们量的是「同一件事两边说法不同时，
> 会不会以私有为准」——客户的专属约定本来就是用来盖住产品默认行为的。
> 区别在于：撞车是**这几道题的题干**，而不是意外。
