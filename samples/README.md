# 样例语料（20 篇）

`docker compose up` 起来之后，init 容器会把这个目录灌进公共知识库，
好让第一次打开这个项目的人**不必先弄到一份真语料**就能提问、看到带引用的答案。

## ⚠️ 这些不是真实语料

每一篇都是**为了这个 demo 手写的**，内容仿照旺店通旗舰版 ERP 的文档形态
（界面路径、参数上限、报错串、版本号），但：

- 所有平台物流编码都带 `SAMPLE-` 前缀（`SAMPLE-JTSD`、`SAMPLE-POSTB`…）；
- 所有 AppKey / 需求 ID / 版本号都是编的（`SAMPLE-90210417`、`9.5.6.8`…）；
- 界面路径是仿写的，**不保证和任何一个真实版本一致**。

线上那套系统跑的是语雀公开知识库的真实快照（746 篇 / 4573 块），
和这个目录没有任何关系。**别拿这里的数字去配客户的系统。**

## 为什么要这么设计

`README.md` 这个文件名会被 `ingest.pipeline.load_yuque_dir` 跳过
（它是目录的说明，不是语料），所以这一页不会变成一篇可检索的文档。

## 试试这几个问题

灌完之后可以问：

- 「订单审核有哪几个前置条件？」——考跨小节的归纳
- 「`SAMPLE-POSTB` 对应哪家快递？」——考裸粘贴一个编码（W1.2 的混合检索）
- 「奇门的 orderType 为什么不支持调拨？该用什么？」——考多条事实的串联
- 「入库预约单是哪个版本加的？」——考版本号这类纯标识符
- 「帮我出一份实施方案」——走多轮收集需求 + 导出 Excel 那条路
